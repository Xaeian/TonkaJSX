# 🌰TonkaJSX

Lightweight _(and probably a bit unfinished)_ **frontend framework**.
It doesn't use ~~**modules**~~ because they make browser debugging harder, but it does support **JSX** because it's great.
Files land in browser **1:1**, so DevTools shows your file, not a bundle.
Script-first, not for huge apps. Zero config, fast setup, for small sites, prototypes, and quick internal tools.

Workspace contains main scripts `serve.js`, `build.js` and `deploy.js`, plus usual **Node.js** stuff.
Each website/app lives in its own project folder inside workspace.
Structure is partly opinionated, but not too strict.

```
ROOT/                  (your workspace folder; name doesn't matter)
├─ tonka.js            (CLI entry: `tonka serve` / `tonka build` / `tonka deploy`)
├─ build.js            (packs project into production `index.html`)
├─ serve.js            (dev server; serves `index.html` if exists else `app.html` + injected links)
├─ deploy.js           (puts built `index.html` on a Cloudflare Worker or into a folder)
├─ utils.js            (shared helpers for `build.js` + `serve.js`)
├─ package.json        (npm config + `bin` for CLI)
├─ package-lock.json   (auto-generated by npm)
├─ readme.md           (this file)
├─ deploy.md           (how deploy picks files and where it puts them)
├─ changes.md          (release notes)
├─ jsstyle.md          (JavaScript and JSX style guide for apps, Tonka UI and the library)
├─ llm.md              (brief for AI assistants)
├─ node_modules/       (npm trash; ignore in docs)
└─ <project-name>/     (one of many projects inside workspace)
   ├─ app.html         (required entry for dev)
   ├─ app.jsx          (optional main file referenced by `app.html`)
   ├─ app.ini          (optional; variables for {{key}} replacement in serve/build)
   ├─ <other>          (other optional referenced by `app.html` JS/JSX/CSS)
   ├─ index.html       (generated by `build.js`; often missing in dev)
   ├─ scripts/         (all JS/JSX source files)
   │  ├─ **/*.js
   │  └─ **/*.jsx
   ├─ styles/          (all CSS/SCSS styles)
   │  └─ **/*.css
   ├─ images/          (static assets, custom)
   ├─ fonts/           (static assets, custom)
   ├─ assets/          (static assets, custom)
   └─ <any-other>/     (videos, data, etc.)
```

Install [Node.js](https://nodejs.org/en/download) first, then clone this repository.
After `install` and `link` that **tonka** command works globally.

```sh
git clone https://github.com/Xaeian/TonkaJSX.git
cd TonkaJSX
npm install
npm link
```

Framework consists of three scripts: a development **server**, a **build** tool and **deploy**, described in [deploy.md](deploy.md).

```sh
tonka serve  [<project-name>] [--port|-p <port>] [--remove|-r]  # start development server
tonka build  [<project-name>] [options]                          # build deploy version of project
tonka deploy [<project-name>] [--worker|-w <key>] [--dry] [-r]   # put built page on a Worker or in a folder
```

Build supports optional optimization flags:

```sh
tonka build -i -f 800kB -s -c -l "Material Symbols"
```

| Flag | Long | What it does |
|:-----|:-----|:-------------|
| `-i` | `--inline-remote [size]` | Inline remote CSS/JS from CDN |
| `-f` | `--fonts [size]` | Drop unused `@font-face`, inline remaining as base64 |
| `-s` | `--svg [size]` | Inline SVGs as data URIs (optimized with SVGO) |
| `-c` | `--compress` | Generate `.gz` + `.br` alongside `index.html` |
| `-t` | `--subset-text "Name"` | Subset text font to chars found in source |
| `-l` | `--subset-ligature "Name"` | Subset icon font to ligatures found in source |

`-t` and `-l` imply `-f`. Without flags, build works as before.
`[size]` is `800kB` or `10MB`, and a file above it keeps its address instead of moving in.
Build then prints how big `index.html` came out and what stayed outside.

Server and build work on chosen project. If you don't pass a project name, it picks the first one _(useful when you only have one)_.
If project contains `app.ini`, variables defined there are replaced in all JS/JSX/CSS/HTML files using `{{key}}` syntax. Top-level values are shared; `[serve]` and `[build]` sections override per mode.
Built-in `{{date}}` and `{{time}}` are always available, and values may reference other vars, e.g. `foot = Build {{date}}`.

```ini
title = TonkaJSX
accent = #d8a57f
[serve]
foot = Serve
[build]
foot = Build
```

If project is built, `index.html` exists and server serves it.
If not, server uses `app.html` and injects styles from `styles/` and scripts from `scripts/`.
With `--remove`/`-r` server first deletes a built `index.html`, so you're sure it serves the app you're editing.
Script order matters: load `.js` first, then `.jsx`. Files in deeper folders load before files in parent folders.
All other files are served as static assets, exactly as they are in project folder.
During build you can inline remote styles and scripts with `--inline-remote` (good for offline use).

## 💡 Example

No imports, no modules, just global components composed with **JSX**.

```jsx
const Greeting = ({ name }) => (
  <div class="greeting">
    <h1>Hello {name}!</h1>
    <p>This is a component.</p>
  </div>
);
const App = () => (
  <div>
    <Greeting name="World" />
    <Greeting name="TonkaJSX" />
  </div>
);
document.body.appendChild(<App />);
```

See built and deployed [**demo**](https://tonkajsx.com), and check files included in this [repo](demo/) for a complete working example.
